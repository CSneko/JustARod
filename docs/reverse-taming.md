# 反向驯服与拍摄

五项正式玩法共用一套服务端逻辑：村民／猫娘拿鱼驯服玩家、主人指令、拿鱼与摸头反应、安全召回、经玩家确认的主人转移。无需开启「荒诞感」，也无需管理员权限。

## 正常游玩

玩家被驯服的功能目前默认关闭。已有的主人关系仍可使用。要恢复喂鱼邀请和首次驯服，在服务端 `config/justarod.json` 中将 `"pet.taming_enabled"` 设为 `true` 并重启服务器，单人世界也可在模组配置界面的「反向驯服」分组中开启。

1. 成年村民和猫娘会在附近空闲时拿鱼示意。空手潜行右键回应，或看向 NPC 按 **K** 打开菜单。只有点击接受才会尝试驯服，每次成功率为 1/3，失败后等待 5 秒再尝试。
2. 成功后，空手潜行右键主人，或按 **K** 与主人互动。可以请求坐下、起立、跟随、摸头和喂鱼。主人也会间隔一段时间主动下令，近距离偶尔摸头；饥饿时会按冷却喂鱼。
3. **X**、移动、跳跃或潜行可以取消当前动作；取消后一分钟内不再主动下令、诱导视线或自动摸头。受伤、死亡、乘坐载具、飞行、换维度或主人卸载时，也会停止当前动作。
4. 跟随是可中断的短距离辅助移动，遇到墙或悬崖会停下。跟随状态下，距离主人超过 12 格会尝试安全召回，每次尝试间隔 5 秒。没有安全落点就等待，不跨维度、不强制加载区块。
5. 主人拿鱼时会短暂吸引视线，移动鼠标即可打断；可在配置界面关闭「拿鱼时的视角反应」。摸头会播放呼噜与爱心，旁观者也能看到反应。
6. 主人转移菜单选择附近的另一名成年村民或猫娘（村民优先选择猫娘），再次确认后才交接。候选者离开、死亡或确认超时均不转移。超时为 30 秒。
7. 猫娘的「跟随／自由活动」控制她自身的简单移动，与玩家跟随主人互斥。

默认按键可以在游戏控制设置中修改。普通右键村民仍然交易，带物品右键仍然走原有互动。

永久保留的普通玩家命令：

```text
/jarpet                 查看主人与状态
/jarpet menu            与附近主人互动
/jarpet cancel          解除动作并暂停自动指令一分钟
/jarpet release         永久解除关系，即使主人未加载也可使用
```

关系保存在玩家存档的 `JustARodPet` 中，与 toNeko 现有的主人列表分开。重登、重生保留主人，坐下／跟随、确认窗口和临时镜头反应不保存。主人区块卸载保留关系；确认主人死亡后解除关系。

新增 `justarod:pet_owner_neko` 为简单猫娘主人，使用已有 `shiuri_neko` 外观和动画，仅配置基础行走、注视和互动。她会少量生成在平原，也可召唤：

```mcfunction
/summon justarod:pet_owner_neko ~3 ~ ~
```

`justarod:dried_fish`（小鱼干）由一份熟鳕鱼无序合成，也可食用。村民展示生鳕鱼，猫娘展示小鱼干。猫娘声音复用前置中的喵声，呼噜复用原版猫音效；可用资源包替换 `justarod:pet_neko_voice` 与 `justarod:pet_purr`。

## 荒诞感

服务端 `config/justarod.json`（此项目使用扁平键）：

```json
{
  "fun.absurdity": false,
  "pet.camera_motion": true
}
```

- 名称：**荒诞感**。
- 介绍：**增加模组一些东西的荒诞感**。
- 默认关闭；多人世界以服务端配置为准。修改配置文件后重启服务器；单人世界可通过模组配置界面切换。
- 开启后，村民向猫娘转移主人关系会出现“三颗绿宝石 → 玩家”的特殊交接界面，确认后展示绿宝石交接。
- 这是剧情交易：不消耗玩家绿宝石、不增加经济系统，也不会让临时展示的道具进入 NPC 背包、存档或死亡掉落。
- 临时导演命令也受该开关控制；普通转移和全部基础玩法不受影响。

开启后，主人还会进入适合连续拍摄的互动行为：

- **固定互动位置**：只接管正在喂鱼、等待交接或已经建立关系的附近 NPC，暂停其工作寻路和闲逛，持续转身面向演员。被轻推后会尝试走回站位；不把 NPC 传送回去。
- **主动推进表演**：建立关系后约 1 秒开始，默认以约 10 秒一个动作的节奏循环：拿鱼吸引注意 → 坐下 → 摸头／招呼靠近 → 起立 → 喂鱼 → 跟随。互动与原有正式玩法共用逻辑，喂鱼冷却缩短为 6 秒；远处或隔墙不会强行触发这些互动。
- **方便开场**：未驯服时，附近 NPC 的拿鱼示意间隔从 20 秒缩短为 5 秒；只有回应过或正在示意的 NPC 会临时停留，不会让全村所有村民停工。
- **保护手动镜头**：菜单或导演指令手动触发动作后，主动互动至少等待 10 秒；确认窗口打开期间不会插入自动动作。
- **交接站位**：候选新主人在确认期间停留；交接成功后，旧主人再停留 6 秒，给反应镜头留出时间。
- **可退出**：X 仍然解除玩家动作并暂停主动互动一分钟，主人保留站位。关闭「荒诞感」、解除关系、玩家离线或离开 64 格范围后，NPC 恢复日常 AI。原有的 `NoAI` 标志不改变，临时站位状态不写入存档。
- **保留必要行为**：受伤、战斗、着火、落水等情况优先让 NPC 使用原有 AI；明确选择“猫娘跟随”时仍然允许她跟随，停下后以当前位置继续站位。

## 临时导演命令

需要管理员权限且开启「荒诞感」。普通互动要求演员与 NPC 同维度且距离不超过 6 格；召回仍检查同维度和安全落点。

```mcfunction
/jar_director tame <玩家> <主人实体>
/jar_director order <玩家> sit
/jar_director order <玩家> stand
/jar_director order <玩家> follow
/jar_director tempt <玩家>
/jar_director pet <玩家>
/jar_director recall <玩家>
/jar_director transfer <玩家> <新主人实体>
/jar_director reset <玩家>
```

`tame` 打开一次必定成功的喂鱼确认，跳过随机判定；`transfer` 打开真实交接确认。演员仍然点击确认。`pet` 跳过摸头冷却；`recall` 跳过距离和自动召回冷却，不跳过落点检查。`reset` 清除本系统的关系、动作和互动冷却，方便重新拍摄，不修改背包、生命值或其他模组的数据。

可给演员命名，方便重复选择：

```mcfunction
/summon minecraft:villager ~2 ~ ~ {Tags:["jar_villager"]}
/summon justarod:pet_owner_neko ~-2 ~ ~ {Tags:["jar_neko"]}
/jar_director tame @s @e[tag=jar_villager,limit=1,sort=nearest]
```

拍摄顺序：喂鱼确认 → 坐下／跟随／拿鱼 → 摸头 → 跟随状态下跑远或导演召回 → 转移确认与三绿宝石界面 → 猫娘摸头与喂鱼。逃跑镜头可直接让玩家步行离开：移动会取消跟随，因此拍摄“逃跑失败”时使用导演 `recall` 触发同一套安全召回逻辑。

拍完删除 `common/src/main/java/org/cneko/justarod/director/`，以及 `JRCommands` 中标注 TEMPORARY 的一行注册。正式玩法、特殊交接界面和存档均不依赖导演命令。

## 验证

```bash
./gradlew :common:verifyMixins :fabric:build :neoforge:build
./gradlew :fabric:runGameTest
./gradlew :fabric:runClientGameTest -PslimeClientTests
```

服务端测试覆盖玩家明确接受、跨玩家凭据与重放、普通／荒诞转移、配置在确认期间关闭、存档加载、实际重生、受伤和区块卸载、安全传送、互动冷却与导演权限。新增回归使用实际开启 AI 的村民和猫娘，验证原版寻路被临时接管、站位与朝向、完整主动互动循环，以及暂停、配置关闭和解除关系后的恢复。客户端测试通过真实网络确认、取消按键、跟随输入和模型渲染检查流程，并保存交接界面截图。

仓库的测试任务使用已有的隔离 toNeko 测试副本，禁用其入口和旧版注入；原始前置和用户存档不受修改。这验证 JustARod 本身，不能替代完整前置兼容性验证。详见 `docs/slime-abilities.md` 的测试说明。
